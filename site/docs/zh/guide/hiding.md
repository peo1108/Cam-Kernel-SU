# Root 隐藏检测

**Root 隐藏检测**页（从功能页或任意应用的配置页打开）让你看到银行应用或游戏眼中的手机，并指出每处泄露背后的**模块**。

只在你点按时扫描，从不在后台运行。每次扫描都会与上次比较：**新**、**无变化**、**已隐藏**。

## 三种视角

1. **以 Root 身份**（`camd hiding-audit`）：异常挂载、`su` 路径、属性、SELinux、应用配置，每项都标出来源模块。
2. **以普通应用身份：**在隔离进程中扫描，内核总会为它卸载模块挂载。用原始系统调用读取文件，并与 libc 比较，以发现挂钩 libc 的模块。这就是非 Root 应用真正看到的。
3. **按应用：**从应用配置页查看该应用自己正在运行的进程（应用必须处于打开状态）。

页面还会列出**隐藏良好**的项目，检查**跳过卸载挂载的配置**，并运行 **TEE 认证**，解释为什么在没有泄露时应用仍可能拒绝。

## 快速修复

**快速修复**开关会同时开启内核卸载挂载、SELinux 隐藏和 Bootloader 隐藏。由模块引起的项目会附带停用该模块的按钮。

## 模块变动后自动检查

模块只在下次开机时挂载，所以在安装、更新或重新启用模块后的首次开机，应用会自动扫描一次并报告哪个模块泄露了什么。点按通知即可打开页面。开关位于**自动**部分（默认开启）。

## 检测规则

检测内容来自一份**签名**的规则文件（ECDSA P-256）。打开页面时最多每 6 小时获取一次新版本，只接受签名有效且版本更高的规则。规则只是数据，从不是代码。

规则跟随 [Duck Detector](https://github.com/eltavine/Duck-Detector-Refactoring)，一款常用的 Root 检测器；页面会显示规则跟随的 Duck Detector 提交。

## SELinux 计时

有些应用通过测量写入 `/proc/self/attr/current` 的耗时来猜测 Root。Cam Kernel SU 的内核与原生 SELinux 一样先检查权限，因此不存在时间差。页面提供与 Duck Detector 相同方式的测量探针（手机繁忙时结果会有波动）。
